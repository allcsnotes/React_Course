# M19-L06 · Route Handlers, Middleware and SEO

> Video: Module 19, Lesson 6. Watch it first, then follow along here.

## What you'll learn

- Route handlers: a `route.ts` file that answers requests with data (`GET`, `POST`, ...), with status codes
- The proxy (`proxy.ts`, called middleware before Next.js 16): one file at the door, with a `matcher`
- Metadata (`metadata`, `generateMetadata`), Open Graph tags and a generated Open Graph image
- `sitemap.ts` and `robots.ts`
- The `Image` component and `next/font`, and what they change
- Four mistakes: no `metadataBase`, an `Image` without a width, a picture from another site, `metadata` from a client component

## Before you start

- Node 24 (`node --version`), Google Chrome is not needed (everything is checked with `curl`). No Docker.
- Versions (from `package-lock.json`): Next.js 16.4.3 (Turbopack), React 19.3.0. Lessons 2 to 5 help.
- The project is the one the starter made with one change: `partialPrefetching` is switched **off** in `next.config.ts` (in development it prints a long warning on every visit). The other lessons keep the starter's setting.
- The site runs on port 5196. All data is a small demo list in `lib/courses.ts`; no other server is needed.
- **Fonts:** `app/layout.tsx` uses `next/font/google`, which downloads the font from Google at build time. That needs internet access. The font numbers in step 8 come from the video; I did not re-run them for this repo.

### 1. What does a chat see?

A chat app does not open the page like a person. It asks the server for the page and reads the head: the title, the description and a picture. With the starter's files (`variants/layout.scaffold.tsx`) the head says "Create Next App", "Generated by create next app" and has no picture. Every page of the site would look like that in a chat or a search engine. Today we fix that and meet the other tools of a real site.

### 2. Route handlers

In Lesson 5 a server action gave a form a hidden endpoint. A route handler is an endpoint **on purpose**, with its own address. A folder with `page.tsx` becomes a page; a folder with `route.ts` answers with data. `app/api/courses/route.ts` is the whole file for `/api/courses`: a function named `GET` (capital letters) receives the standard web `Request`, reads `max` from the address, and `Response.json` turns the list into JSON with the right headers.

```ts
import { courses } from '@/lib/courses'

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url)
  const max = Number(searchParams.get('max') ?? Infinity)
  return Response.json(courses.filter((c) => c.price <= max))
}
```

```bash
curl -s -w '\nstatus %{http_code}\n' "http://localhost:5196/api/courses?max=450"
```

```text
[{"slug":"sql-in-two-weeks","title":"SQL in Two Weeks","blurb":"Ask a database real questions.","price":399}]
status 200
```

Status 200 means all went well, and back comes one course (SQL in Two Weeks, 399); the others cost more. A folder in square brackets is a dynamic segment (Lesson 2). The second argument holds the parameters, a promise in this version, so we `await` it, and answer 404 with a short message instead of crashing when the course does not exist:

```ts
import { findCourse } from '@/lib/courses'

export async function GET(
  _request: Request,
  ctx: RouteContext<'/api/courses/[slug]'>,
) {
  const { slug } = await ctx.params
  const course = findCourse(slug)
  if (!course) {
    return Response.json(
      { error: 'Course not found' },
      { status: 404 },
    )
  }
  return Response.json(course)
}
```

```text
/api/courses/sql-in-two-weeks   -> 200 {"slug":"sql-in-two-weeks","title":"SQL in Two Weeks",...}
/api/courses/nope               -> 404 {"error":"Course not found"}
```

A route handler can also receive data. A `POST` function reads the body with `request.json()`. If the email or the course is missing it answers 400; otherwise 201 (created). Anybody on the internet can send anything to this address, so we check what comes in, as with server actions:

```ts
export async function POST(request: Request) {
  const body = await request.json()
  if (!body.email || !body.course) {
    return Response.json(
      { error: 'email and course are required' },
      { status: 400 },
    )
  }
  return Response.json(
    { ok: true, enrolled: body.course },
    { status: 201 },
  )
}
```

```bash
curl -s -w '\nstatus %{http_code}\n' -X POST -H 'content-type: application/json' \
  -d '{"email":"lukas@example.com","course":"sql-in-two-weeks"}' http://localhost:5196/api/enroll
```

```text
{"ok":true,"enrolled":"sql-in-two-weeks"}
status 201
```

With only an email: `{"error":"email and course are required"}` and status 400. A method we never wrote, like `DELETE` on `/api/courses`, gets **405** (method not allowed) for free.

Is an answer made once at build time, or at every request? The build prints a table: a circle (`○`) means static, `ƒ` means dynamic.

```text
Route (app)
┌ ○ /
├ ○ /_not-found
├ ○ /api/about
├ ƒ /api/courses
├ ƒ /api/courses/[slug]
├ ƒ /api/enroll
├ ○ /courses
├   /courses/[slug]
│ ├ ◐ /courses/[slug]
│ ├ ○ /courses/react-for-beginners
│ ├ ○ /courses/sql-in-two-weeks
│ └ ◐ [+2 more paths]
├ ƒ /courses/[slug]/opengraph-image
├ ○ /images/after
├ ○ /images/before
├ ○ /robots.txt
└ ○ /sitemap.xml


ƒ Proxy (Middleware)
```

`/api/about` reads nothing from the request, so it is static, and its answer carries a cache header (`cache-control: s-maxage=31536000`, kept for one year). `/api/courses` reads the address, so it runs every time and has no cache header.

### 3. The proxy

Picture the guard at the door of an office. Every visitor meets the guard first, before any room. The guard can send a visitor to another door, hand them a badge, or let them in. In Next.js that guard is one file in the project root. In older versions it was called `middleware.ts`; in the version installed here (16.4.3) it is called `proxy.ts`.

```ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  if (request.nextUrl.pathname === '/old-courses') {
    return NextResponse.redirect(
      new URL('/courses', request.url),
    )
  }
  const response = NextResponse.next()
  response.headers.set('x-seen-by', 'proxy')
  return response
}

export const config = {
  matcher: ['/old-courses', '/courses/:path*'],
}
```

If the path is `/old-courses` it redirects to `/courses`. For every other request it lets Next.js continue and adds one header, `x-seen-by`. The `config` at the bottom is the matcher: the list of paths where the guard stands. Without a matcher the proxy would run for every request, even for pictures and files; keep it small and fast. The proxy is for quick decisions, not for slow data. Real run:

```text
GET /old-courses                  -> HTTP/1.1 307 Temporary Redirect, location: /courses
GET /courses/sql-in-two-weeks     -> HTTP/1.1 200 OK, x-seen-by: proxy
GET /api/about                    -> no x-seen-by header (not in the matcher)
```

Guess: if you rename `proxy.ts` back to `middleware.ts`, does the site still run, or break? Real run (`variants/middleware.ts` is the old-name file):

```text
The "middleware" file convention is deprecated. Please use "proxy" instead.
  npx @next/codemod@canary middleware-to-proxy .
```

It still runs, with that warning. With **both** files present the build stops:

```text
Error: Both middleware file "./middleware.ts" and proxy file "./proxy.ts" are detected. Please use "./proxy.ts" only.
```

So in this version use `proxy.ts`; in an older tutorial middleware is the same idea with the old name.

### 4. Metadata

The head holds facts about the page that are not shown in it: the title, the description and tags for chat apps; it is like the label on a parcel. In Next.js you describe them in an object called `metadata`, and Next.js writes the tags. `app/layout.tsx` holds the metadata of the whole site:

```tsx
import type { Metadata } from "next";
import { Inter } from "next/font/google";
import "./globals.css";

const inter = Inter({ subsets: ["latin"] });

export const metadata: Metadata = {
  metadataBase: new URL("http://localhost:5196"),
  title: { default: "allcsvideos", template: "%s | allcsvideos" },
  description: "Learn to code with short, clear video courses.",
};

export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html lang="en">
      <body className={inter.className}>{children}</body>
    </html>
  );
}
```

`metadataBase` is the address of the site, so that every link can be made complete. The title has a default and a template: `%s` is where the title of each page goes. A course page needs its own title from its own data, so instead of an object it exports a function, `generateMetadata`, which gets the parameters as a promise, finds the course, and returns a title, a description and Open Graph tags (what chat apps and social sites read to build the preview card):

```tsx
import type { Metadata } from 'next'
import { notFound } from 'next/navigation'
import { courses, findCourse } from '@/lib/courses'

export function generateStaticParams() {
  return courses.map((c) => ({ slug: c.slug }))
}

export async function generateMetadata({
  params,
}: PageProps<'/courses/[slug]'>): Promise<Metadata> {
  const { slug } = await params
  const course = findCourse(slug)
  if (!course) return { title: 'Course not found' }
  return {
    title: course.title,
    description: course.blurb,
    openGraph: {
      title: course.title,
      description: course.blurb,
      type: 'website',
    },
  }
```

Real run, the head of `/courses/sql-in-two-weeks`:

```text
<title>SQL in Two Weeks | allcsvideos</title>
<meta name="description" content="Ask a database real questions."/>
<meta property="og:title" content="SQL in Two Weeks"/>
<meta property="og:description" content="Ask a database real questions."/>
<meta property="og:image" content="http://localhost:5196/courses/sql-in-two-weeks/opengraph-image?219e7f1aba393735"/>
<meta property="og:image:type" content="image/png"/>
<meta property="og:image:width" content="1200"/>
<meta property="og:image:height" content="630"/>
<meta property="og:type" content="website"/>
<meta name="twitter:card" content="summary_large_image"/>
```

We did not write the image tags. They come from `app/courses/[slug]/opengraph-image.tsx` next to the page: it draws a 1200x630 picture for each course with `ImageResponse`, and Next.js adds the tags. Fetching it gives `200 image/png` (35,269 bytes in my run). Now the chat has a title, a description and a picture.

### 5. Site map and robots

Search engines send robots to read websites. The site map is a list of every page you want found; ours is a function in `app/sitemap.ts` that makes one address for the home page and one for each course from the same list, so adding a course grows the site map by itself. The robots file is a function too: every robot may visit everything except `/api/`, and here is the site map.

```text
$ curl -s localhost:5196/sitemap.xml | grep -oE '<loc>[^<]*</loc>'
<loc>http://localhost:5196</loc>
<loc>http://localhost:5196/courses/react-for-beginners</loc>
<loc>http://localhost:5196/courses/sql-in-two-weeks</loc>
<loc>http://localhost:5196/courses/python-from-zero</loc>
<loc>http://localhost:5196/courses/system-design-basics</loc>

$ curl -s localhost:5196/robots.txt
User-Agent: *
Allow: /
Disallow: /api/

Sitemap: http://localhost:5196/sitemap.xml
```

Both are circles (made once) in the build table. In production these addresses carry your real domain, not localhost.

### 6. Pictures

Pictures are usually the heaviest part of a page. `/images/before` shows `public/banner.jpg` in a plain `<img>`: the browser downloads the whole file (879,747 bytes with the banner my script made; the video's was 880,031) and, when it arrives late, it pushes the text down. That jump is a **layout shift**. `/images/after` uses the `Image` component from `next/image`:

```tsx
import Image from 'next/image'

export default function After() {
  return (
    <main>
      <h1>React for Beginners</h1>
      <Image
        src="/banner.jpg"
        alt="Course banner"
        width={2400}
        height={1350}
        sizes="480px"
        style={{ width: '100%', maxWidth: 480, height: 'auto' }}
        preload
      />
      <p>Build your first React app, from zero.</p>
    </main>
  )
}
```

We give it the real `width` and `height` of the file, so the browser keeps the space free before the picture arrives, and `sizes` tells it how wide the picture will be on screen (480 pixels). Behind the scenes Next.js makes smaller copies on request, in a lighter format (WebP), and sends the one that fits the screen:

```text
plain file:        879747 bytes   (GET /banner.jpg)
optimised (w=640): 2882 bytes, image/webp   (GET /_next/image?url=%2Fbanner.jpg&w=640&q=75, Accept: image/webp)
```

The video measured 880,031 against 10,223 bytes at its chosen width, a largest paint of 976 ms against 208 ms on a 10 Mbit/s network, and a layout shift of 0.0325 against 0. One fair warning: the banner is a generated picture, smooth and simple, so it shrinks more than a photo would. Your numbers will differ.

### 7. Fonts (not re-run)

A plain `<link>` to a font service makes the browser contact another company's server first, and the text may change shape when the font arrives. `next/font/google` downloads the font at build time and serves it from your own site, with a matching fallback so the text barely moves. In `app/layout.tsx` that is `import { Inter } from "next/font/google"`, `const inter = Inter({ subsets: ["latin"] })` and `<body className={inter.className}>`. In the video, on the course list, the plain link made two requests to other servers (`fonts.googleapis.com` and `fonts.gstatic.com`) and `next/font` made none; the font file was the same size (about 48,000 bytes), and the layout shift went from 0.0018 to 0.0002. Both are tiny, so the real win is the missing trip to another server. (`variants/layout.fontbefore.tsx` and `variants/layout.fontafter.tsx` are the two layouts. I did not run them because they contact Google.)

## Common mistakes

1. **No `metadataBase`** (`variants/layout.nobase.tsx`). The build prints a warning and the picture address in the head says `localhost:3000`, which is wrong for everybody else. Fix: set `metadataBase` in the layout, with your real address.

```text
⚠ metadataBase property in metadata export is not set for resolving social open graph or twitter images, using "http://localhost:3000".
```

2. **An `Image` without a width** (`variants/mistakes/m2.page.tsx`). In development the page fails:

```text
Error: Image with src "/banner.jpg" is missing required "width" property.
```

   Fix: give `width` and `height`, the real size of the file.
3. **A picture from another website** (`variants/mistakes/m3.page.tsx`). Next.js refuses:

```text
Error: Invalid src prop (https://images.example.com/banner.jpg) on `next/image`, hostname "images.example.com" is not configured under images in your `next.config.js`
```

   This stops strangers from using your server to resize any picture on the internet. Fix: list the host under `images.remotePatterns` in `next.config.ts` (`variants/mistakes/m3.next.config.ts`); the page then renders (status 200).
4. **`metadata` exported from a client component** (`variants/mistakes/m4.page.tsx`: the page starts with `'use client'`). The build stops:

```text
Error: You are attempting to export "metadata" from a component marked with "use client", which is disallowed. "metadata" must be resolved on the server before the page component is rendered.
```

   Fix: keep the page as a server component and move the button into its own client file (`m4.EnrollButton.tsx` and `m4.fixed.page.tsx`).

## Clean up

Stop the site. Delete `.next/` and `node_modules/`. `public/banner.jpg` is made by the script and git-ignored.

## Key points

- A route handler is a `route.ts` file that answers with data: `GET`, `POST` and more. The proxy (called middleware before Next.js 16) is one file at the door, with a matcher, for quick decisions.
- Metadata, `generateMetadata`, Open Graph, a site map and a robots file tell chat apps and search engines what each page is. Always set `metadataBase`.
- Use the `Image` component and `next/font`. Measured in this lesson: 879,747 bytes down to 2,882 for the image, and no request to another server for fonts.

Interview tip. If Rahul, the interviewer, asks "how does Next.js help with SEO?": the server sends complete HTML with the title, the description and the Open Graph tags, a site map lists the pages, and images and fonts are optimised, so the page loads fast and does not jump.
